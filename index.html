A* pathfinding

CS380 · C++ · course project
PROBLEM
Agents on a grid map need paths that are optimal and also look natural. Raw A* output hugs corners and zig-zags.
APPROACH
A* with my own open and closed lists and a choice of heuristics (Manhattan, Chebyshev, Euclidean, Octile). Rubberbanding then drops waypoints that have a clear line of sight, using Bresenham's algorithm, and Catmull-Rom splines smooth what's left.
OUTCOME
Paths that are straightened and smoothed, so the agent walks them without snapping at corners.
LEARNED
The line-of-sight check for rubberbanding took the longest, and understanding how the four spline control points work together was the other big step.

Outdoor noise pollution

CS380 · C++ · course project
PROBLEM
Build a lively scene out of behaviour trees: agents that react to each other and to mouse clicks.
APPROACH
I wrote 15 nodes (a looping sequencer, repeat-until-fail and timer decorators, and leaves such as wave, jump, spin, spawn ball and kill nearest) and combined them into five trees, with the framework's blackboard sharing data between nodes. At an outdoor concert the fans wave, jump and vibe to the music until a giant red killer bird, which waits eight seconds, dives and takes out the noisy crowd. Clicking the map also spawns bouncing balls.
OUTCOME
A scene built entirely from reusable nodes. New behaviour means a new tree, not new control code.
LEARNED
Getting the bird's celebration to play once without restarting the whole tree took the most time, and so did tracing how mouse input travels from the framework into a leaf node.

Rock & Ghoul

CSD2451 · C++17 · team game on a custom engine
ROLE
Tech lead and programmer on Team Avid Divas, a team of eight. I built much of the engine's editor tooling.
THE GAME
You play Rock, half of a guitar duo. Spirits attack before a gig, and you fight them with melee swings and spells cast by arrow-key sequences.
ENGINE
A custom C++17 engine with FMOD audio, C# scripting through Mono and FFmpeg video cutscenes, plus a dockable ImGui editor so designers can build levels and cutscenes without touching code.
MY PART
I wrote about half of the editor code (roughly 8,000 lines, shared with two teammates). It covers the game view with play/stop testing, scene manager, entity inspector and prefabs, asset browsers, and a build-size analyzer. I also wrote the undo/redo system on my own. It covers adding and deleting entities, gizmo moves, and any component property, and keeps the last 30 actions. The editor can also create a new game from scratch: it sets up the project folders, audio manifest, default font and a starter main.cpp, then switches to it.
OUTCOME
A playable build with menus, audio and cinematics that you can install and try.
